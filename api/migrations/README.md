# Migrations

Managed with [node-pg-migrate](https://github.com/salsita/node-pg-migrate). `DATABASE_URL` must be set (see repo README for a local Postgres via Docker).

```bash
npm run migrate:up --workspace api      # apply pending migrations
npm run migrate:down --workspace api    # revert the last migration
npm run migrate:create --workspace api -- my-migration-name
npm run db:seed --workspace api         # run seeds/*.sql in order
```

## Conventions

- **Immutable once merged.** CI fails any PR that modifies or deletes an existing file in this directory — write a new migration instead. (Enforced by the `migrations` CI job.)
- Filenames: `<timestamp>_<kebab-case-description>.cjs` (generated by `migrate:create`).
- Every migration must have a working `down`.
- Table/column naming: `snake_case`, plural table names, `created_at`/`updated_at` timestamps, soft delete via `deleted_at` (see KUR-004 for the base conventions).
- Concurrent deploys are safe: node-pg-migrate takes an advisory lock by default, so two instances can't run migrations at once.
